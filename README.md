# Meeting Intelligence

面向 macOS 26+ 的原生会议录音和转写应用，使用 SwiftUI、Core Audio Process Tap、AVFoundation 和 Apple Speech，无第三方运行依赖。

已实现：指定应用录音、可选麦克风分轨录音、录制中分段转写、字幕保存和失败续转、历史记录、双轨混听/单轨回放、点击字幕回听、菜单栏控制和主窗口内设置。支持可扩展的 provider 接口，目前提供 Apple 本地转写和 Qwen-Audio 3.1 会后异步精校。说话人识别、摘要和 SQLite 索引尚未接入。

## 构建与运行

```sh
./scripts/build-app.sh
open 'build/Meeting Intelligence.app'
```

需要 macOS 26+ 和对应 Swift SDK。本机使用 Command Line Tools / Swift 6.4.2。脚本优先使用本机唯一的 Apple Development 或 Developer ID Application 证书签名，也可通过 `MEETING_CODESIGN_IDENTITY` 指定签名身份；没有唯一可用证书时回退到 ad-hoc 签名。保持同一签名身份可避免每次构建后钥匙串重新识别应用。生成的应用不是公证分发版本。请通过 `.app` 运行，以便 macOS 正确识别权限用途声明。

1. 在新录制页面选择目标应用。浏览器以整个应用为范围，不区分标签页。
   常用应用按腾讯会议、Chrome、飞书、微信、Meeting 优先排列，其后包括 Zoom、钉钉、企业微信、Teams、Webex、Slack、FaceTime、华为云会议、WeLink、瞩目、小鱼易连、好视通、全时、会畅等。仅展示正在运行的应用；名单内应用静音时仍保留，其它应用默认按音频输出活动筛选，也可勾选“显示所有运行中的应用”。网页版 Google Meet 等会议请选择承载会议的浏览器。
2. 按需勾选麦克风，使用系统默认输入设备；首次使用会请求麦克风权限。麦克风使用普通共享输入；建议佩戴耳机，以获得最佳录音与转写质量，减少扬声器声音被麦克风重复收录。
3. 本地转写始终开启，默认使用中文，启动时自动准备 Apple 系统语音资源。语言切换和资源状态只在设置中展示；缺少资源时自动联网下载，语音识别在本机执行。
4. 点击“开始录音”，按 macOS 提示允许系统音频录制权限。分别检查应用和麦克风输入状态。
5. 已关闭的音频片段约每 10 秒送入识别，字幕带来源与会议时间戳；这是分段更新，并非逐字即时字幕。停止录音后自动补转最后不足 10 秒的片段。
6. 历史会议支持“继续本地转写”和单独的“云端转写”，失败重试不重复已保存的片段。点击字幕会从对应时间开始回听，可选择混听、仅应用音频或仅麦克风。
7. 在转写结果页打开“导出”菜单，可选择“导出转写＋音频”（单个离线 HTML，内嵌合并音频）、“导出音频”（M4A）或“导出转写”（不含音频的 HTML）。HTML 保留时间戳及应用音频／麦克风角色，支持关键词搜索；包含音频时，还支持点击发言回听、倍速播放和跟随高亮。文件无需联网或配套目录即可打开，内嵌音频的体积约比原音频大三分之一。转写尚未完成时导出当前快照。音频始终混合应用与麦克风的完整音轨，与当前回放选择无关，保留原始时间线和静音间隔，并预留混音余量。支持取消导出和在 Finder 中显示文件；失败或取消不会覆盖已有目标文件。

转写失败、缺少模型或资源不足不会丢弃音频；录音可独立继续。资源就绪后可回到历史会议继续转写。转写语言随会议固定；设置中的语言仅用于新会议及首次补转写的旧会议。

## Qwen-Audio 3.1 云端精校

1. 打开“设置 → 云端转写服务”，Provider 选择“Qwen-Audio 3.1”。设置只配置服务，不代表授权上传；旧版本的本地转写关闭偏好不再生效。
2. 选择北京或新加坡。点击“前往百炼创建 API Key ↗”，在对应地域的百炼控制台创建 Key，粘贴后点击保存。Key 按地域保存至 macOS Keychain，不写入 UserDefaults、录音清单或字幕 JSON。保存仅检查格式并写入 Keychain，不代表在线鉴权已验证。
3. Workspace ID 可选；填写后使用业务空间专属域名，留空使用地域标准域名。需保证 Key、业务空间、模型权限和余额可用。
4. 在新录制页面按场勾选“本次录制使用云端转写”（默认关闭）。本地字幕始终自动生成，勾选后在停止录音时使用 `qwen-audio-3.1-asr-flash-filetrans` 按约 10 秒片段提交异步任务。开启一个新的录制页面或结束录制后，该开关重置为关闭，避免下一场自动上传。未勾选的历史会议可直接点击详情中的“云端转写”补做，也可在本地转写进行时点击以排队精校；已启用会议继续使用其保存的地域及配置。
5. 每个片段成功后，校验句级毫秒时间戳，加上原始片段的会议偏移，原子替换该片段本地字幕。点击文字仍从原录音对应时间回听；来源保持应用音频 / 麦克风。失败片段保留已有文字，已完成片段不会重转。
   百炼返回 `ASR_RESPONSE_HAVE_NO_WORDS` 时，将该片段标记为已处理并保留本地结果，继续后续片段；详情显示未识别到语音的片段数。这与本地静音过滤分开统计，不表示该片段免费。旧版因此中断的会议可直接“继续云端转写”，复用已有任务查询结果。
6. “暂停转写”停止本机查询及后续提交，无法保证已接受的云端任务停止处理或计费。继续和重启后使用保存的 task ID 查询，不重新上传已有任务。

提交超时可能已经产生云端任务。应用会先持久化“提交中”标记，不自动重发这种不确定请求。确认控制台后可选择“核对任务后重新提交未完成片段…”；确认弹窗会提示可能重复计费。任务失败、取消、结果过期也需要核对后显式重新提交。结果链接官方有效期 24 小时，成功后立即保存到本地。

启动和显示配置状态时只检查钥匙串条目元数据，并禁止该检查弹出授权窗口；实际使用云端转写时才读取 Key。成功读取或保存后仅在当前进程内存中复用，修改和删除 Key 会同步更新缓存。旧版 ad-hoc 签名切换为证书签名后，首次访问旧条目仍可能需要授权；确认应用后选择“始终允许”可记住授权。钥匙串锁定或仅选择单次允许时，之后仍可能提示。

“跳过整段静音”默认开启：扫描所有声道，只有整段各声道峰值 ≤−80 dBFS 且 RMS ≤约−90 dBFS 时才跳过上传。轻声、噪声、音乐和有声片段内的停顿仍会上传；这是保守能量门限，不是完整语音活动检测（VAD）。原录音不会裁剪，时间轴无需重映射。非静音仅生成临时 16 kHz / 单声道 / PCM16 WAV 副本，立体声内容混合，严重反相抵消时保留能量最大的声道；完成或失败后清理副本。

界面显示按音轨累计跳过的静音时长；仅在接口返回 Token 用量时显示用量，不将未返回的用量假装为零费用。应用音频与麦克风分别上传、分别计量；转换采样率/位深减少上传体积，不承诺按同比例减少 Token 或账单。

当前采用百炼官方临时文件上传接口（有效期 48 小时），适用于个人接入验证。官方不推荐该机制用于生产、高并发或压测；正式分发前应增加受控 OSS 上传和生命周期管理，provider 协议可保持不变。临时云端文件没有在本版本中主动删除的接口实现，请按供应商保留政策处理。

协议、凭据和异步任务适配在 `MeetingCore` 内，新增 provider 实现 `TranscriptionProvider`，并注册凭据/工厂及设置项即可。当前不提供任意第三方 API 地址输入。

接口依据：[Qwen Filetrans HTTP API](https://help.aliyun.com/zh/model-studio/qwen-audio-asr-filetrans-api/)、[本地文件临时上传](https://help.aliyun.com/zh/model-studio/get-temporary-file-url)、[模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)。Token 用量和实际费用以账户账单为准。

## 耳机录音与转写角色

- 推荐耳机播放会议声音，麦克风使用系统默认输入设备。应用音频由 Process Tap 采集，麦克风使用普通 AVAudioEngine 输入，两路分轨保存。
- 不创建 VoiceProcessingIO，不提供系统回声消除开关，也不读取旧版的实验性模式偏好，以避免再次启用曾干扰会议软件收音的处理链路。
- 使用扬声器时仍可能重复收录。当前不通过静音麦克风或删除相似字幕来消重，以保留双方同时发言和重复确认的内容。
- Transcript 的 `source` 固定为 `application`（应用音频）与 `microphone`（麦克风）；不是按说话人身份分组。旧录音和字幕继续可读，历史采集模式元数据保留。
- 录制中切换扬声器、耳机或默认麦克风时，先保存当前片段，再自动重建采集；设备暂未就绪时每 0.5 秒重试，最多等待 12 秒。保持同一条会议和原始时间线，切换期间未采到的声音保留为空隙；新片段记录各自的采样率和声道数。重建输出时保留正常工作的麦克风，避免反复切换蓝牙音频模式。恢复期间可结束录音；超过等待时间仍无法恢复时保存为中断并提示原因。具体耳机与会议软件的并行收音仍需现场验证。

## 存储和恢复

默认音频：`~/Library/Application Support/Meeting Intelligence/Recordings/<UUID>/`。
默认字幕：`~/Library/Application Support/Meeting Intelligence/Transcripts/<UUID>.json`。

设置页面可独立选择音频和字幕目录。目录配置保存至 `settings.json`；开关和语言保存至应用的 UserDefaults。变更前检查写权限，失败时保留原配置。新目录仅用于新会议，旧数据保留原位并继续可读。每场会议的清单记录实际字幕位置，之后改变设置不会使旧字幕丢失。

- 每个音频来源独立分段，以同一 host-time 起点对齐，保存来源、采样格式、偏移和有效时长。文件采用设备采样率、16-bit PCM；48 kHz 立体声约 691 MB/小时，麦克风另计。
- 实时回调仅向有界 C11 SPSC 缓冲区复制数据；落盘、音量计算与识别不在实时回调执行。
- 先登记清单，再写 `*.partial.wav`；关闭文件后 rename 为 `.wav`，原子更新清单。异常退出后恢复已关闭片段，保留未完成文件；最后一段可能缺失。
- 双轨共用一份清单，由串行采集队列写入，避免并发覆盖。旧版无 source 字段的音频自动视为应用音频。
- 字幕 JSON 包含版本、语言、引擎、来源、起止时间、已处理片段和任务状态。每个片段识别结束后原子保存；重启可继续未完成任务。损坏的字幕文件不会被静默覆盖。
- 识别逐段从磁盘读取；落后时无需在内存排队保存音频。每段识别设有 60 秒超时。分段边界可能影响个别词语，当前不提供跨段语境校正。
- 回放保留采集间隙，并为双轨使用相同播放起点；同一来源的不同格式使用独立播放节点，由系统混音器转换采样率和声道，支持设备切换前后的片段连续播放、定位和音轨选择。加载时逐个检查文件头，播放时仅保留接下来约 30 秒内的文件，避免长会议耗尽文件句柄。
- 退出正在录制的应用会先询问并完成音频保存。后台转写被退出打断时，已提交字幕保留，重启后可继续。

应用图标为侧栏灰底波形；构建后刷新该应用的 LaunchServices 注册，启动时显式设置 Dock 图标。默认使用 Apple 本地转写；只有按场开启云端转写或在历史会议中主动补做，并配置 Key 的会议，才会上传音频进行精校。

## 诊断日志

在“设置 → 诊断日志 → 打开日志目录”查看本机运行日志，默认目录为 `~/Library/Logs/Meeting Intelligence/`。`app.jsonl` 是当前日志，每行一条 JSON；单文件上限约 2 MB，保留当前文件和 3 个历史文件，自动轮换。日志与录音目录独立，不随录音导出。

日志记录启动版本、构建时间与提交版本，云端上传/提交/轮询/结果下载阶段、HTTP 状态、供应商错误码、request ID、task ID、会议和片段 ID，以及音频设备恢复和播放失败。不会写入 API Key、请求头、签名 URL、音频、字幕或原始响应正文。诊断目录仅当前用户可访问。此日志不是完整崩溃报告；异步落盘在异常退出时可能缺少最后几条记录。

遇到云端错误时，请记下发生时间，并保留日志目录中的 JSONL 文件。旧记录保留的失败提示不代表本次又发起了请求：可按 `cloud.saved_state` 和 `cloud.http.*` 区分历史状态与新请求。新版本不会补录旧版运行日志；点击“继续云端转写”后，已有任务会复用 task ID 查询，故障定位可结合对应的 request ID。不要为收集日志使用“重新提交”来重复创建收费任务。

## 验证

```sh
./scripts/test.sh
```

常规测试使用合成 PCM、临时目录和模拟 HTTP，不录制真实会议、不调用收费云端 API。覆盖分段内容、双轨时间偏移与不同采样率、短尾段、旧数据兼容、异常恢复、损坏文件、缓冲区并发、离线混音/seek、字幕时间戳和持久化、失败续转、识别中到达最终快照的收尾行为。

真实 Apple Speech 集成测试默认跳过，需要本机模型和合成语音文件：

```sh
say -v Tingting -r 150 -o /tmp/meeting-speech-zh.aiff '今天我们讨论会议记录功能。请保存录音，并且生成带时间戳的文字。'
MEETING_SPEECH_FIXTURE=/tmp/meeting-speech-zh.aiff \
MEETING_SPEECH_LOCALE=zh-CN MEETING_SPEECH_EXPECTED=会议 \
./scripts/test.sh
```

当前测试覆盖双轨写入、尾段、启动预热门控、固定双角色、历史采集模式兼容及字幕持久化。此前的 VoiceProcessingIO 硬件验证不代表会议软件共享兼容；该处理链路已移除。

设备切换回归使用合成 PCM 验证同场会议的多采样率/声道片段、双轨时间偏移、切换间隙、原始样本保存、恢复期间结束保存、时钟回退保护及重试截止时间；尚需实际耳机切换验证。

云端新增测试覆盖上传请求、鉴权隔离、轮询限流、任务续查、子任务失败、不确定提交、句级时间戳、本地替换与失败保留、暂停和跨重启恢复、静音判定、轻声与反相/分离立体声。尚未使用真实 Key 验证百炼账户权限、临时文件上传支持及真实会议精度/成本。

尚需真实硬件验收，不能用合成样本替代：指定应用 A/B 声音隔离、麦克风权限拒绝与拔插、真实会议识别质量、30–60 分钟双轨时钟漂移、连续录制资源占用及突然断电恢复。尚未宣称完成长会议可靠性验收。

Swift 6.4 CLT 的 TestingMacros 自动发现存在问题，测试脚本显式加载工具链自带插件。链接器可能报告未使用的 Developer 搜索目录缺失；构建和签名校验可完成。

## 工程结构

- `Sources/RealtimeAudio`：实时回调和有界缓冲区。
- `Sources/MeetingCore`：应用音频匹配、双轨采集、分段写入、清单与字幕持久化、Apple Speech、转写任务队列、回放调度。
- `Sources/MeetingIntelligence`：原生窗口、录音协调、字幕界面、播放器、设置与菜单栏。
- `Tests/MeetingCoreTests`：自动化测试和可选本地 Speech 集成测试。
- `design/figma-reference`：设计参考，不作为运行依赖。

原始阶段计划见 [PLAN.md](PLAN.md)，界面约定见 [design/UI-SPEC.md](design/UI-SPEC.md)。

### 会议回放与管理

- 详情页底部使用原生玻璃效果的悬浮播放条，滚动转写时保持可见。真实音频波形支持拖动定位、键盘调节及 VoiceOver，保留静音间隔；切换应用／麦克风音轨时更新波形。
- 点击详情标题直接修改名称，回车或离开输入框保存，Esc 取消；侧边栏右键也可选择“重命名”。
- 标题右侧和侧边栏右键菜单提供“删除记录”。确认后先停止该记录的回放与转写，再将录音目录及对应转写一起移到废纸篓；已导出的文件保留。外置转写会收纳到被删除的录音目录中。该记录导出期间不能删除。

记录详情页使用固定会议信息和操作栏、独立滚动的转写正文，以及固定底部播放条。点击发言可回听，工具栏的定位按钮可返回当前播放位置；继续／暂停转写、云端精校和转写设置位于更多菜单，用量信息可在“转写详情”中展开。
